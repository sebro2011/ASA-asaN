## 1. Executive summary

The audit found **six substantive scientific defects** and **twelve smaller
correctness and robustness issues** in the statistical layer. Every one is fixed
or explicitly disclosed. No feature was removed, no API field was deleted, no UI
surface was redesigned, and no existing test assertion was weakened.

The single most important finding is that the project's own methodological
specification and its implementation disagreed about the significance threshold —
and the implementation used the value the project's own calibration study had
**rejected**. That is corrected, and a test now fails if the document, the code
and the UI ever drift apart again.

The second most important finding is that implementing the *published* Hamed–Rao
recipe literally is **anti-conservative** at n = 30, and the project's specified
variant (zeroing negative lags) is measurably better. Both are now computed and
exposed so the choice is auditable rather than asserted.

**Nothing in this report is claimed as validated beyond what was measured.** Every
number below is printed by `npm run verify:stats` from the shipped code path.

## 3. The alpha threshold inconsistency

### 3.1 What was wrong

The same threshold appeared in four places and they disagreed:

| Location | Value | Role |
|---|---|---|
| `docs/earth-lab/03_STATISTICAL_METHOD.md` §4.3 | **α = 0.01** | the specification |
| `climateStatistics.ts` default parameter | **α = 0.05** | what actually ran |
| `TrendDetective.tsx` stats panel | `α = 0.05 (two-sided)` | what the user was told |
| any test | *nothing asserted it* | why nobody noticed |

The document is not arbitrary about this. §4.3 reports a measured false-positive
rate of **4.2 % at α = 0.01 versus 13.0 % at α = 0.05** under AR(1) φ = 0.6. The
shipped code used the rejected value, so the tool showed readers "significant"
verdicts at roughly three times the rate its own documentation deemed acceptable.

### 3.2 What it is now

`src/lib/earth/statisticsConfig.ts` holds every threshold in one frozen object.
Nothing in the statistics layer, the UI, or the tests writes a literal threshold.

```ts
trendAlpha: 0.01        // the published verdict
literalAlpha05: 0.05    // keeps `significantAt05` meaning exactly what it says
literalAlpha01: 0.01
comparisonAlpha: 0.05   // for the non-trend comparisons (see §5)
```

### 3.3 Before / after

| | before | after |
|---|---|---|
| verdict threshold | 0.05 | **0.01** |
| UI label | hard-coded `α = 0.05 (two-sided)` | `describeTrendAlpha()` → `α = 0.01 (two-sided)` |
| `significantAt05` | the verdict | unchanged meaning (`p < 0.05`), no longer drives the verdict |
| new `significant` field | — | `p < STATISTICS_CONFIG.trendAlpha` |
| drift detectable? | no | `npm run test:method-consistency` reads the doc and the UI as text and asserts agreement |

### 3.4 Why `significantAt05` was kept

Deleting it would have been a **silent** semantic change for any consumer reading
it. It keeps its literal historical meaning, and the verdict moved to a new field.
A test pins both.

## 4. Hamed–Rao autocorrelation correction

### 4.1 Four deviations from the published formulation

Hamed & Rao (1998), *J. Hydrol.* 204:182–196, defines

```
n/n* = 1 + 2·Σ_k (n−k)(n−k−1)(n−k−2)·ρ_k / (n(n−1)(n−2))
```

with ρ_k the lag-k autocorrelation **of the ranks of the detrended series**, and
only lags whose ρ_k exceeds ±1.96/√n contributing.

| # | Documented | Previously implemented | Corrected |
|---|---|---|---|
| 1 | ρ from **ranks** of detrended series | ρ₁ from raw **values**, ρ₂…ρ_k from ranks | all lags from ranks ✓ |
| 2 | significance gate ±1.96/√n | `\|ρ_k\|` summed, no gate, sign flipped | negative lags **zeroed** per spec §4.2 ✓ |
| 3 | lags 1…min(n−3, ⌊n/3⌋) | lags 1…min(n−3, **10**) | ⌊n/3⌋ rule ✓ |
| 4 | effective sample size n\* | not computed, not exposed, not gated | `effectiveSampleSize`, enforced ✓ |

Item 2 deserves emphasis because it is the one where the *documented* rule and the
*published* paper's rule disagree, and the document is right.

### 4.2 Measured consequence — this is the important result

600 seeded AR(1) replicates, n = 30, **no trend**, false-positive rate at α = 0.05
(reproduce with `npm run verify:stats`):

| φ | uncorrected MK | literal published recipe | **shipped (spec) recipe** | shipped at α = 0.01 |
|---|---|---|---|---|
| 0.0 | 4.7 % | 9.8 % | **1.3 %** | 0.2 % |
| 0.3 | 16.3 % | 18.0 % | **5.3 %** | 0.7 % |
| 0.6 | 30.8 % | 26.2 % | **12.2 %** | 4.3 % |
| 0.8 | 47.0 % | 30.0 % | **17.7 %** | 8.2 % |

**Implementing the paper literally is not enough.** The literal recipe is worse
than the specified one at every φ. The reason is visible in the arithmetic: a
strong negative lag is genuine signal in an AR(1) process, and retaining it shrinks
Var(S) below its independent value, so the test over-rejects. Zeroing negative lags
forces n/n\* ≥ 1 by construction, so the correction can only ever add doubt.

Both factors are now computed and exposed as `varianceInflationFactor` (shipped,
clamped) and `varianceInflationFactorPublished` (literal, unclamped), so a reviewer
can audit the difference instead of taking it on trust.

### 4.3 The honest limitation

At φ = 0.6 the analytic correction still rejects **12.2 %** at α = 0.05. It is
not calibrated; it is **less wrong** than the alternatives, and α = 0.01 brings it
to 4.3 %. This is stated in the code, in the doc, and on the panel. No claim of
calibration is made anywhere.

## 5. Effective sample size eligibility

### 5.1 What was missing

The specification §4.4 requires three refusal rules; none were implemented:

| Rule | Was | Now |
|---|---|---|
| n < 10 | implemented | ✓ (via config) |
| **n\* < 10 → refuse** | **absent** | ✓ `inferenceEligible = false`, p, Z\* and CI all `null` |
| 10 ≤ n\* < 14 → `short record` | **absent** | ✓ `confidence: 'short-record'` |

### 5.2 Behaviour

A 20-year random walk — the physically important case, where a drifting climate
record looks like the strongest possible trend and carries almost no evidence —
now yields:

```
eligible:            true    (the record is long enough to compute)
effectiveSampleSize: 7.25
inferenceEligible:   false   (below the floor of 10)
pValue:              null
direction:           'insufficient-data'
senSlopePerDecade:   available and labelled descriptive
```

The descriptive slope is **not** hidden — it is real information about the window —
but it carries no inferential claim.

### 5.3 The aggregated verdict

`buildTrendVerdict` combines the annual MK, seasonal MK and Pettitt into one
conclusion with four rules:

1. If the annual test cannot infer, publish **nothing**.
2. Confidence is the **minimum** of its inputs — never the maximum.
3. If the annual and seasonal tests disagree about whether a trend exists, the
   verdict falls back to `no-trend` and the dissent is **named**, not averaged.
4. Pettitt tests a *step*, not a monotonic trend, so it never votes on direction;
   it is reported as a dissenting observation when it finds a step the monotonic
   tests miss.

## 6. Student's and Welch's t-tests under temporal dependence

### 6.1 What was wrong

`computeHistoricalSplit` compares the earlier and later halves of **one** climate
record, then handed those two halves to `tTest`, which assumes 2n independent
observations. Annual climate records are strongly autocorrelated, so the standard
error was understated.

Measured, 12-vs-12-year epoch split, no true difference, α = 0.05:

| φ | plain t-test false positives |
|---|---|
| 0.0 | 5.0 % (nominal ✓) |
| 0.3 | 12.3 % |
| 0.6 | **28.7 %** |
| 0.8 | **45.3 %** |

At φ = 0.6 a textbook t-test calls roughly **three in ten trend-free epoch
differences "significant"**.

### 6.2 What was built, and what was rejected

I tested three approaches and measured each before shipping:

| approach | φ = 0 | φ = 0.6 | verdict |
|---|---|---|---|
| null block-bootstrap permutation p-value | 8.2 % | 27.0 % | **rejected** — worse than the t-test at φ = 0 |
| moving-block bootstrap CI on the mean difference | 37 % | 56 % | **rejected** — broken at φ = 0 |
| **√VIF standard-error inflation + effective-n gate** | **3.2 %** | **2.5 %** | **shipped** |

The bootstrap variants fail because a 12-vs-12 split of *one* realization has only
~24 points and ~2 blocks per epoch; the resampling has nothing to work with. That
is a property of the data, not of the implementation, and it is why the
specification's §6.1 already refuses formal difference tests at this sample size.

The shipped correction: inflate the standard error by √VIF, where VIF is the
exact finite-n AR(1) variance inflation of the mean, estimated from the **larger**
of the raw and the Sen-detrended lag-1 autocorrelation (the conservative choice —
de-trending can destroy the dependence signal in a persistent record).

### 6.3 Before / after

| φ | plain false positives | shipped false positives | withheld |
|---|---|---|---|
| 0.0 | 5.0 % | 3.2 % | 0.3 % |
| 0.3 | 12.3 % | 3.7 % | 7.8 % |
| 0.6 | 28.7 % | **2.5 %** | **50.0 %** |
| 0.8 | 45.3 % | 1.0 % | 76.0 % |

The trade is explicit: false positives fall roughly tenfold, and the price is that
about half of φ = 0.6 records are **refused** rather than answered. For a
public-facing climate tool, refusing is the right direction — and the naive
p-value is still disclosed so nothing is hidden from a reviewer.

Power is preserved: a real 3-unit epoch shift is still detected, and a 100 %
detection rate holds for the trend test.

### 6.4 Backwards compatibility

A bare `tTest(x, y)` still defaults to `structure: 'independent'`, so existing
consumers behave exactly as before. Callers comparing epochs of one record must
pass `structure: 'serial-blocks'`; `computeHistoricalSplit` does. Either way the
result always reports the measured `lag1Autocorrelation`, the applied
`varianceInflationFactor`, and a `dependenceWarning` when the observed serial
correlation is material — so declaring the wrong structure is **visible, not
silent**.

## 7. Seasonal Mann–Kendall

### 7.1 What was wrong

The seasonal test summed the *independent-sample* Var(S_m) across calendar months
and applied **no autocorrelation correction whatsoever**. Monthly values within a
calendar month are serially correlated year to year, so the combined variance was
understated and the test over-rejected — the same defect the annual test had.

### 7.2 What is now done

Hirsch & Slack (1984) within-season correction: apply the Hamed–Rao inflation
factor to each month's variance **before** summing.

```
Var*(S) = Σ_m Var(S_m) · (n_m/n_m*)
```

Each factor is ≥ 1, so the combined test can never become more liberal than the
uncorrected one. `rawVariance`, `variance` and `withinSeasonVarianceInflation` are
all exposed.

### 7.3 Additional fixes

- Per-month duplicate years are collapsed (previously double-counted).
- A degenerate (constant) record reports `p = 1, no-trend` instead of an
  `insufficient-data` refusal — matching the annual test and specification §4.4.
- Eligibility thresholds come from the config, not literals.
- An effective-observations gate now also applies.

## 8. The dependence-aware alternative: block bootstrap on S

### 8.1 Why the obvious construction was not shipped

The project's own §7.3 had already rejected a percentile bootstrap CI on the Sen
slope. I confirmed it and tested two replacements:

| construction | φ = 0 | φ = 0.6 |
|---|---|---|
| percentile bootstrap CI on the Sen slope | 16.8 % | 23.3 % |
| inverted-null bootstrap CI on the Sen slope | 13.0 % | 24.0 % |
| **circular block bootstrap on S (shipped)** | **4.0 %** | **9.0 %** |

The slope-based intervals fail **at φ = 0**, where there is no autocorrelation to
blame at all. A 30-point Sen-slope sampling distribution is too discrete for a
percentile interval to be honest. S is bounded, integer-valued and free of nuisance
parameters, so bootstrapping it behaves.

### 8.2 The method

Centre the series (under H₀ there is no trend, so de-meaning is the
null-preserving step — **not** de-trending, which I measured to manufacture a null
centred away from zero). Resample with a circular moving block of ⌈n^(1/3)⌉.
Recompute S. Report `p = (1 + #{|S*| ≥ |S_obs|}) / (B + 1)` with B = 999 and a
**fixed seed**, so the output is bit-identical across runs (asserted by test).

The bootstrap is reported **alongside** the analytic test and can only ever add
doubt: the verdict requires the analytic test to pass at α as well.
`inferenceAgreement` states which way the two differ.

### 8.3 Limitation

At φ = 0.6 it still rejects 9.0 % at α = 0.05 and 3.0 % at α = 0.01. It is a real
improvement over an uncorrected test (30.8 %), not a solution. A 30-year
autocorrelated record cannot fully identify its own trend.

## 9. Confidence intervals, p-values, edge cases, numerical stability

| Issue | Before | After |
|---|---|---|
| `erfc` accuracy | Abramowitz & Stegun 7.1.26, **absolute error 1.5e-7**, hard `0` for \|z\| ≳ 5.7 | routed through the incomplete gamma; **~1e-12 relative**, deep tails preserved (p(z=6) = 1.97e-9, not 0) |
| `erfc` far tail | `1 − P` cancels to 0 in double precision | new `regularizedGammaQ` evaluates Q directly |
| Sen 95 % CI | clamped indices into the available pair range | `null` when `k1 < 0` or `k2 > N`, per specification §3 — never a fabricated bound |
| CI critical value | always 1.959964 | `z_{1−α/2}` from α (2.5758 at α = 0.01) |
| reported p-values | `round(p, 6)` turned 3e-9 into **`0`**, i.e. "impossible" | new `roundP` floors at 1e-6; a reported p is **never exactly 0** |
| `Var(S) = 0` | `continuityZ` returned 0 with no guard on the tie correction going negative | variance clamped at ≥ 0; constant series reports `p = 1`, `no-trend` |
| duplicate years | double-counted in S | collapsed to the first record |
| non-finite input | filtered | filtered (unchanged) and tested |
| empty series | worked | tested |
| unsorted input | sorted | sorted, and tested that order does not matter |
| Sen slope with gaps | time index = row index | uses **actual elapsed years** |
| extreme magnitudes (1e12, 1e-12) | untested | tested for NaN/Infinity |
| heavy ties (3 levels over 30 points) | untested | tested for a non-negative variance |
| Pettitt p | unclamped `2·exp(...)` | clamped to [0,1]; underflow yields the reporting floor, never NaN |

## 12. Remaining scientific limitations

These are stated because they are true, not to be modest.

1. **The corrected MK test is not calibrated.** At φ = 0.6 the false-positive rate
   at α = 0.05 is 12.2 %. α = 0.01 brings it to 4.3 %. A 30-year record cannot
   fully resolve its own autocorrelation; no correction changes that.

2. **The block bootstrap is not calibrated either.** 9.0 % at φ = 0.6, α = 0.05.

3. **The epoch-split t-test correction is first-order.** The √VIF inflation reduces
   but does not eliminate over-rejection, and it achieves that partly by withholding
   ~50 % of φ = 0.6 comparisons. That is a deliberate false-negative-for-false-positive
   trade, documented in the code.

4. **No block-bootstrap inference is shipped for epoch comparisons.** All variants
   measured failed at φ = 0. The specification's CI-overlap screen remains the only
   comparison mechanism, and it is labelled a screen.

5. **Pettitt has no dependence correction.** Its asymptotic p-value assumes
   exchangeability. This is disclosed via `dependenceWarning`, not fixed. The change
   year is additionally the argmax over n−1 candidates, so it carries more
   uncertainty than its p-value implies.

6. **The rank-detrended autocorrelation underestimates persistence.** I measured
   ~0.35 from a detrended estimator against a true φ = 0.9. This is why the
   variance factor is conservative and why the effective-n gate refuses so often.

7. **Multiplicity is not corrected.** The specification §5.2 asks for
   Benjamini–Hochberg across the k tests shown together; three tests are displayed
   side by side and no BH is applied. The interpretation strings now say so
   explicitly ("not corrected for multiple comparisons"). **This remains an open
   item**, deliberately not implemented here because it changes result semantics for
   a set of tests and deserves its own review.

8. **`pValue` and `significantAt05` semantics are unchanged by design.** A consumer
   that reads `significantAt05` still gets the 0.05 answer. Migrating consumers to
   `significant` is a follow-up.

9. **No live NASA POWER retrieval was exercised.** No network access to POWER from
   this environment; all tests use synthetic POWER-shaped fixtures. The integration
   was verified only through the existing mocked suites.

10. **No real-browser render check.** DOM tests use jsdom/shared render harness;
    the components were smoke-rendered for all three languages but not visually
    inspected at 1440/834/390 px in a real browser.

## 14. What to review

The changes most deserving scrutiny:

1. **`statisticsConfig.ts`** — `trendAlpha: 0.01` is a *behaviour change* that will
   make past "significant" results no longer significant. This is the specification's
   own decision, but it is a user-visible change and should be signed off.

2. **§4.2 above** — the finding that the literal published Hamed–Rao recipe is
   anti-conservative at n = 30. If a reviewer disagrees, the shipped rule is one
   config value away from changing, and both factors are already computed.

3. **The epoch-split refusal rate.** ~50 % of φ = 0.6 records now return "not
   resolvable" instead of a p-value. That is the intended trade, but it will look
   like a regression to a user who was previously shown a confident answer.

4. **`tTest` defaulting to `structure: 'independent'`.** This preserves backwards
   compatibility at the cost of requiring callers to opt in. The
   `dependenceWarning` mitigates it but does not eliminate the footgun.
